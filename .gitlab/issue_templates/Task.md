# Summary

* **Description**: Describe the functionality this adds/repairs/... to the software product. You may also want to describe what parts of the codebase this likely concerns. If this task is about fixing a bug, document the bug exactly. This allows others to validate - after your work - whether they can reproduce that your work fixes the bug.
* **Notes**: Add notes for later; e.g. when drafting the task in a sprint planning meeting.

> Use `/estimate` to indicate how much time you estimate the task will consume. For example, `/estimate 2h` indicates that you expect the task will consume 2 hours.  
> Later on, use `/spend` in a comment to indicate how much time you have spent on this task. For example, `/spend 3h` indicates that you have spent 3 hours on this task.
> Make sure to assign the task to the user that should be working on it!! If it is supposed to be worked on by more than one user, tag the second user in the description or comment of this task, to be able to trace who is supposed to be working on this.
> Link the task to a user story (aka milestone)
> Move the task to the appropriate list in the issue board
